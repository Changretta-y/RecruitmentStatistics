## 业务规则与公开契约

- MCP 远程入口为 `/mcp`，采用 Streamable HTTP；每个请求都通过 `Authorization: Bearer` 认证，Token 必须绑定当前 MCP 资源受众。
- MCP 服务必须发布 `/.well-known/oauth-protected-resource/mcp`；未认证 `/mcp` 返回 `401`，`WWW-Authenticate` 指向该文档。
- OAuth 服务必须发布 Authorization Server Metadata 并声明 CIMD 支持；DCR 只作为旧客户端兼容选项，不是必需能力。授权码流程必须支持 PKCE `S256`、精确 redirect URI、`state`、`resource=https://<host>/mcp` 和 `applications:read` 最小 scope。
- 服务以 stateless/no protocol session 为主，不依赖进程内 Session 保存现代请求状态，首期现代路径不返回也不要求 `Mcp-Session-Id`；官方 SDK v2 可兼容 `2025-11-25` 旧客户端 handshake/session，但不能让现代请求依赖旧 session。
- MCP 工具列表只暴露 `find_applications`；工具为只读，不得触发写入。
- `find_applications` 必须使用 APP-012 的公司聚合公开结构，结果自动限定为 OAuth Token 对应用户；不接受 `user_id` 等越权参数。
- 具体字段、示例、错误和验收口径以 `docs/requirements/MCP-001.md` 为唯一任务契约。

## 输入、输出与错误行为

- 发现文档：公开 `200 application/json`；内容中的 issuer、resource、endpoint、scope、PKCE 声明必须与实际配置一致。
- 缺少、无效、过期或受众不匹配 Token：HTTP `401`，带 RFC 6750 风格 `WWW-Authenticate`；不得执行 MCP 方法。
- Token 缺少 `applications:read`：HTTP `403`，返回 `insufficient_scope`。
- 现代合法请求通过 `server/discover`、`tools/list` 发现工具，再通过 `tools/call` 调用查询；不把 `initialize` / `notifications/initialized` 作为现代请求的必经步骤。若声明兼容 `2025-11-25`，再单独验证旧 handshake 路径。
- `find_applications` 的正常结果同时提供可读 `content` 和结构化 `structuredContent`；无匹配返回空分页，不返回跨用户信息。
- 非法 PKCE、redirect URI、resource、重复授权码、非法工具参数或未知方法必须稳定拒绝，不能泄露 Token、密码、授权码或内部堆栈。

## 验收标准

- [ ] Protected Resource Metadata 和 Authorization Server Metadata 可公开发现；Authorization Server Metadata 声明 CIMD 支持，且 `WWW-Authenticate` 能把未认证 MCP 客户端导向正确发现文档；DCR 不作为必需能力。
- [ ] 合法公共客户端以 CIMD HTTPS metadata URL 作为 `client_id` 完成 Authorization Code + PKCE `S256` 流程，换取 scope 为 `applications:read` 且受众为 `/mcp` 的 Access Token；非法 verifier、redirect URI、resource、过期/重复 code 均被拒绝。
- [ ] `/mcp` 支持 MCP `2026-07-28` 的 stateless/no protocol session 请求：现代客户端可完成 `server/discover`、工具列表和工具调用，不需要先执行 `initialize`；若实现声明旧客户端兼容，另有 `2025-11-25` handshake 回归证据。
- [ ] `tools/list` 只暴露 `find_applications`，其输入 JSON Schema 明确定位、筛选和分页字段，并标识只读语义。
- [ ] `find_applications` 返回 APP-012 公司/岗位/共享阶段/面试聚合结构和分页元数据；无匹配为空结果；调用不改变数据库。
- [ ] 两个用户通过各自 OAuth Token 查询时严格数据隔离；跨用户 ID、公司名、岗位名和伪造用户参数均不能读取对方数据。
- [ ] 测试 Agent 只通过公开 HTTP/JSON-RPC 和数据库可观察结果先形成 `RED_CONFIRMED`；功能实现 Agent 不修改测试目录；独立复测通过后才进入项目管理验收。

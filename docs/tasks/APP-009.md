## 业务规则与公开契约

- 每个登录用户可创建公司投递记录；一个公司记录包含一个或多个岗位投递。公司归属仍严格按当前用户隔离。
- 每个公司记录包含公司级共享流程：AI 面、测评、笔试；每种最多一条，时间可空、可设置或清空。共享流程在公司下任一岗位视图中语义相同，不复制成各岗位各自独立的数据。
- 每个岗位包含零到多条面试流程记录；同一岗位可有多个面试环节，也可重复出现同一环节（例如追加二面或复试）。每条记录有稳定 ID、环节名称、可空时间及现有时长语义；编辑/删除一条记录不得改动其他记录。环节名称去首尾空格后必填。
- 将已有六个固定阶段 API 迁移到嵌套结构：`ai_interview_time`、`written_test_time` 作为公司共享流程；旧 `first_interview_time`、`second_interview_time`、`third_interview_time`、`hr_interview_time` 分别转成相应岗位下的面试记录。既有时长映射到对应流程；未填写时间的历史流程不生成记录。
- 迁移同一用户下公司名去首尾空格且不区分大小写后相同的旧记录时，聚合为同一公司并保留所有岗位。若历史记录对同一公司级阶段含有多个不同非空时间，保留时间最早的一条作为共享时间，迁移过程中须在实现说明中记录冲突数量与处理规则。岗位记录及岗位字段不得丢失。
- REST 继续使用 `/api/v1/applications/` 作为公司投递集合：列表/创建返回公司对象；详情、PATCH、DELETE 使用公司对象 ID。成功响应包含 `id`、`company_name`、公司级 `shared_stages`、`positions`、状态及时间戳。岗位对象包含 `id`、`position_name`、状态、投递时间、备注与 `interviews`。面试对象包含 `id`、`name`、`scheduled_at`、`duration_minutes`。
- 创建或修改公司对象时，可在 `positions` 中新增/修改岗位；岗位 ID 只接受该公司现有岗位 ID，省略的既有岗位不删除。删除公司投递按既有硬删除行为级联删除岗位和流程。岗位与面试的删除须由契约定义并以岗位/面试子资源标识，不允许用省略字段隐式删除。
- 共享流程 API 的唯一键为公司 + 类型；重复提交同一类型时按更新该唯一记录处理，不产生第二条。岗位面试使用子资源 ID 增删改。
- 搜索公司名、岗位名、状态筛选、排序和分页仍按既有公开行为工作；列表分页单位为公司对象。`current_stage` 可继续返回，但必须明确按公司级共享阶段与岗位面试记录计算，取最近一个已安排/已完成的阶段；本任务不改变已有状态枚举。
- 写入仍接受 ISO 8601 或 `null`；未认证返回 `401`，不存在或跨用户资源返回 `404`，结构/类型/重复无效输入返回 `400 VALIDATION_ERROR`，失败请求不产生部分更新。

## 输入、输出与错误行为

- `POST /api/v1/applications/` 接收 `company_name`、`shared_stages`、至少一个 `positions` 项；每个岗位可包含 `position_name`、状态、投递时间、备注及 `interviews`。
- `PATCH /api/v1/applications/{id}/` 可局部更新公司字段、共享阶段和岗位；成功返回完整嵌套公司对象。PATCH 缺失字段不变；显式 `null` 清空可空日期/时长。
- 面试子资源路由固定为 `POST /api/v1/applications/{company_id}/positions/{position_id}/interviews/`、`PATCH /api/v1/applications/{company_id}/positions/{position_id}/interviews/{interview_id}/`、`DELETE /api/v1/applications/{company_id}/positions/{position_id}/interviews/{interview_id}/`。岗位删除使用 `DELETE /api/v1/applications/{company_id}/positions/{position_id}/`。响应返回创建/更新后的对象；删除返回 `204 No Content`。
- 创建时提交只读 ID、空公司名/岗位名/面试名称、无岗位公司、非法日期或非法时长均返回字段级 `400`；PATCH 中的子 ID 仅作定位，关联资源不存在/不属于该公司/不属于当前用户均返回 `404`；失败不留下公司、岗位或流程的部分数据。

## 验收标准

- [ ] 一个公司可创建并返回多个岗位；详情/PATCH 后岗位信息、各自状态、备注和投递时间独立保存。
- [ ] AI 面、测评、笔试每种在同一公司最多一条；任一岗位可读写共享日期，重复设置同类型会更新而不是另建。
- [ ] 一个岗位可新增多个面试记录且可重复环节名；仅改动/删除指定面试时其他面试及其他岗位数据不变。
- [ ] 既有数据迁移保留全部岗位及既有时间/时长；历史公司级阶段冲突遵循契约的确定性规则，报告冲突数量。
- [ ] 列表、详情、创建、修改、删除、搜索、状态过滤、分页均以公司聚合为单位，权限和字段错误行为符合契约。
- [ ] 任何包含嵌套数据的写入具有原子性；无效子项不会造成部分落库。

# APP-004 分页与每页数量

- 状态：`DONE`
- 用户价值：记录较多时可以稳定翻页并控制每页数量，不因超大请求拖垮服务。
- 范围：应用列表 `page`、`page_size`、页码边界和统一分页响应。
- 非范围：搜索、筛选、排序 UI；数据库全文检索。
- 依赖：`APP-003`。
- 允许修改范围：测试 Agent：`backend/tests/`、`docs/test-reports/`；实现 Agent：`backend/apps/`、`backend/config/`、`docs/implementation-notes/`；项目管理 Agent：仅 `docs/requirements/`、`docs/tasks/`、`docs/acceptance/`。

## 业务规则与公开契约

- 默认 `page=1`、`page_size=20`。
- `page_size` 允许 10、20、50、100，最大 100；非法值必须按固定约定返回 `400 VALIDATION_ERROR`，不得静默使用任意大值。
- `page` 最小为 1；超出范围按项目统一约定返回空结果或 404，但必须固定并测试。推荐返回 `200` 空 `results` 并保留总数。
- `next`、`previous` 必须保留现有筛选/排序 query 参数。

## 验收标准

- [x] 默认响应为 20 条且页码字段准确。
- [x] 10/20/50/100 均生效，超过 100 或非法值行为稳定。
- [x] 翻页不跨越用户隔离范围，next/previous 链接参数完整。
- [x] 空数据和超出页码行为符合任务约定。
- [x] 测试先验证分页契约缺失，再由实现和独立复测通过。

## 风险与测试边界

- 页码测试需使用超过一页的本人数据，并确认其他用户数据不计入 count。
- 前端改每页数量回到第 1 页由 `WEB-APP-002` 负责。

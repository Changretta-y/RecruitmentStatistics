# WEB-MAIL-001 每日邮件通知设置页面

- 状态：`DONE`
- 用户价值：从账号页面配置并管理每日安排邮件。
- 范围：收件邮箱、每日时间、启用开关、验证流程、状态/错误展示。
- 非范围：服务端调度和真实发信、个人 SMTP 凭据录入。
- 依赖：`MAIL-001` 完成；需求 `docs/requirements/CAL-001.md` 第 5、8 节。
- 允许修改范围：项目管理 Agent 仅 `docs/requirements/`、`docs/tasks/`、`docs/acceptance/`；测试 Agent 仅 `frontend/tests/`、`tests/e2e/`、`docs/test-reports/`；实现 Agent 仅 `frontend/src/`、`docs/implementation-notes/`。

## 业务规则与公开契约

- 登录用户从页面导航进入通知设置，查看当前收件邮箱、验证状态、每日北京时间、开关、固定时区“北京时间（Asia/Shanghai）”及最近一次发送日期/状态；`unknown` 显示“发送结果待核实”。
- 用户可编辑收件邮箱和 `HH:mm` 时间；保存后新地址显示待验证并禁用推送，用户可发送验证邮件并在验证完成后开启。变更地址时提示旧地址立即停用。
- 未填完整信息或未验证地址时开关不可成功开启；关闭后不再发送。页面不收集或回显发信账号密码。
- 验证邮件发送反馈、限流、令牌无效/过期、网络和 `5xx` 错误均可理解，表单输入在失败时保留。提交期间防重复点击；时区显式标注。
- 验证链接落地路由为 `/notification-settings/verify?token=...`；页面读取令牌后立即从地址栏移除查询参数，调用验证 API，成功或失败均不持久化令牌，且在清除前不加载第三方资源。

## 输入、输出与错误行为

- 输入/输出遵循 `MAIL-001` 的本人设置及验证 API；401 沿用认证刷新/退出机制。
- `400` 映射到邮箱/时间/启用字段，`429` 告知稍后再试；请求结果不确定时重新获取设置，不虚报已启用或已验证。

## 验收标准

- [x] 进入设置页可查看本人配置和时区；邮箱、每日时间与开关保存后重新进入保持一致。
- [x] 新地址待验证、旧地址停用、验证成功后可启用；未验证或资料不完整不能启用。
- [x] 输入错误、429、401、网络/服务端失败有清楚提示且不泄露凭据，失败表单可继续编辑。
- [x] 页面只要求收件地址与推送时间，不要求用户填写平台 SMTP 发信凭据；时间明确标注“北京时间（Asia/Shanghai）”。

## 风险与测试边界

- 验证链接可能出现在浏览器历史或访问日志；入口应及时清除 URL 参数，服务端和前端日志均不得记录令牌。
- 测试模拟公开 API 响应，不读取前端实现目录。

# E2E-001 核心端到端流程

- 状态：`DONE`
- 用户价值：从真实浏览器和服务入口验证用户能完成完整核心流程，而非仅通过孤立单元测试。
- 范围：Playwright 注册、登录、持久化、增删改查、搜索筛选分页、自动刷新和退出保护。
- 非范围：第三方登录、移动原生应用、性能压测、全量浏览器矩阵。
- 依赖：`WEB-AUTH-003`、`WEB-APP-004`、`SEC-001`、`DOC-001`。
- 允许修改范围：测试 Agent：`tests/e2e/`、`frontend/tests/`、`backend/tests/`、`docs/test-reports/`；实现 Agent：仅按回归失败修改 `backend/apps/`、`backend/config/`、`frontend/src/` 和 `docs/implementation-notes/`；项目管理 Agent：仅 `docs/requirements/`、`docs/tasks/`、`docs/acceptance/`。

## 公开流程契约

- 流程 1：注册 → 登录 → 进入列表。
- 流程 2：新增记录 → 列表可见 → 刷新浏览器/服务后数据仍在。
- 流程 3：设置笔试和一面时间 → 刷新后准确显示 → 清空一面时间。
- 流程 4：多条记录 → 搜索/筛选/排序 → 翻页 → 切换 10/20/50/100。
- 流程 5：删除并确认 → 列表更新；取消删除无变化。
- 流程 6：模拟 Access 过期 → 单次刷新 → 原请求成功；退出后受保护页不可访问且旧 Refresh 不能使用。

## 验收标准

- [x] 上述核心流程在隔离测试数据和真实公开入口上通过。
- [x] 失败截图/日志能定位到页面、请求和响应，不通过修改断言规避失败。
- [x] 浏览器刷新、服务重启和跨用户访问均覆盖数据持久化/隔离。
- [x] E2E 测试在本轮使用项目声明的 Node/Playwright 环境和锁定依赖运行。
- [x] 测试 Agent 已提交 `TEST_PASSED`，并列出生产编排器、非 Chromium 浏览器及多实例/负载均衡等未覆盖风险。

## 风险与测试边界

- E2E 不替代后端权限单测、前端拦截器测试和模型测试；三者均需保留。
- 自动刷新测试应使用可控的测试 Token/clock，不把等待 30 分钟作为测试步骤。

# APP-001 投递模型、迁移与当前阶段派生

- 状态：`DONE`
- 用户价值：系统具备持久化个人投递记录的统一数据结构，六个阶段可独立为空。
- 范围：`JobApplication` 模型、迁移、状态枚举、时间字段、索引和 `current_stage` 派生规则。
- 非范围：CRUD API、分页筛选、前端表格、提醒和统计。
- 依赖：`DB-001`、`AUTH-001`。
- 允许修改范围：测试 Agent：`backend/tests/`、`docs/test-reports/`；实现 Agent：`backend/apps/`、`backend/config/`、迁移和 `docs/implementation-notes/`；项目管理 Agent：仅 `docs/requirements/`、`docs/tasks/`、`docs/acceptance/`。

## 业务规则与公开契约

- 表名为 `job_applications`，记录属于一个 User，删除用户级联删除记录。
- 必填 `company_name`、`position_name` 最大 200 字符；去首尾空格后不能为空。
- `application_status` 只允许 `applied`、`in_progress`、`offer`、`rejected`、`withdrawn`，默认 `applied`。
- `application_time`、AI 面、笔试、一面、二面、三面、HR 面时间均为可空带时区时间；`notes` 默认为空字符串。
- `created_at`、`updated_at` 自动维护；不对同一用户同公司/岗位强制唯一。
- `current_stage` 不单独存库，按 HR 面 > 三面 > 二面 > 一面 > 笔试 > AI 面 > 已投递派生；终态状态优先展示终态。

## 验收标准

- [x] 空数据库迁移后模型可持久化，默认状态和六个空时间正确。
- [x] 时间保存/读取保留时区语义，更新时间在修改时变化。
- [x] 当前阶段覆盖空记录和六个阶段优先级，并正确处理终态。
- [x] 用户删除会级联删除记录；模型索引至少覆盖用户+更新时间、用户+状态、用户+公司名。
- [x] 迁移和模型行为先有 RED，再由实现和独立复测完成。

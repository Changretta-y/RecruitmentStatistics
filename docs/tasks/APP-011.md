## 业务规则与公开契约

### 1. 八值下拉与旧值

前端所有投递业务状态选择器、筛选器和状态标签只使用以下顺序和值：

`applied/投递` → `assessment/测评` → `written_test/笔试` → `first_interview/一面` → `second_interview/二面` → `other_interview/其他轮次` → `hr_interview/HR面` → `rejected/拒绝`。

`in_progress`、`offer`、`withdrawn`、`ai_interview`、旧中文文案和未知值不可写入或作为应用状态筛选值。历史值按 APP-010 规则归一，`in_progress` 依流程映射，`offer`/`withdrawn`→`rejected`，实现说明记录每种数量，公开响应不出现旧值。

### 2. 保存状态与最新流程投影

- `positions[*].application_status` 是唯一可编辑的保存状态；`current_stage` 是只读、非持久化的最新流程投影。
- 公司共享 `assessment`→`assessment`、`written_test`→`written_test`、`ai_interview`→`other_interview`；岗位“一面”→`first_interview`、“二面”→`second_interview`、HR 面→`hr_interview`；三面、复试、终面及未命中的自定义面试→`other_interview`。
- 除保存状态为 `rejected` 时终态优先外，取所有带 `scheduled_at` 流程中时间最新者；同一时间按 `hr_interview` > `other_interview` > `second_interview` > `first_interview` > `written_test` > `assessment`，再按稳定 ID 裁决；没有流程时间时回退到保存的 `application_status`。
- AI 面的运行时投影为 `other_interview` 只影响 `current_stage`；填写、编辑或清空任何流程时间不得隐式改写保存状态。显式修改保存状态不得改写时间或时长。

### 3. 主页面、表单和筛选

- 编辑表单每个岗位只有一个业务状态下拉，选项严格为八项；值绑定保存的 `application_status`，不可将只读 `current_stage` 当作第二个选择器。
- 主列表公司首岗位行和展开岗位行各只显示一个状态标签，文案取岗位 `current_stage`；列表不得永远从保存值渲染而隐藏已有流程。
- 刷新、分页、搜索、编辑返回、重新打开详情后，标签必须与公开 API 的 `current_stage` 一致。无流程时保存的“二面”等状态也必须保持，不得退回“投递”。
- 状态筛选仍通过 URL `applicationStatus` 和 API `application_status`，只提供八项，并按有效 `current_stage` 匹配公司下任一岗位；旧应用 `stage` 参数返回 `400 VALIDATION_ERROR`，日历 `stage` 不变。

### 4. API 投影、错误和隔离

- 嵌套 `positions[*]` 返回 `application_status` 与 `current_stage`；顶层兼容字段分别为主岗位保存值和主岗位派生值。两者可不同，但都只允许八值。
- POST/PATCH 只接受保存字段，任何 `current_stage` 写入均字段级拒绝；成功返回重新计算的投影。共享只读返回与主岗位一致，不泄露备注和其他岗位私有字段。
- 未认证为 `401`，跨用户/不存在资源为 `404`，非法状态、旧值和非法筛选为字段级 `400 VALIDATION_ERROR`；失败不产生部分写入。

## 输入、输出与错误行为

### 合法输入与输出

```json
{
  "positions": [
    {
      "id": 52,
      "position_name": "后端开发",
      "application_status": "applied",
      "interviews": [
        {"name": "二面", "scheduled_at": "2026-10-06T10:00:00+08:00", "duration_minutes": 60}
      ]
    }
  ],
  "shared_stages": [
    {"type": "written_test", "scheduled_at": "2026-10-05T10:00:00+08:00", "duration_minutes": 60}
  ]
}
```

成功的 GET/POST/PATCH 应在该岗位返回 `application_status: "applied"` 与 `current_stage: "first_interview"`、`"second_interview"`、`"other_interview"` 或其他按规则确定的八值；不得因保存值仍为 `applied` 而把最新流程投影固定为 `applied`。具体响应保留 APP-009 的嵌套字段、分页和时间格式。

### 非法输入

- 下拉/API 写入旧值、未知值、中文展示名或 `current_stage`：`400 VALIDATION_ERROR`，错误详情指向对应字段，不得部分更新。
- 应用列表携带旧/非法 `application_status` 或 `stage`：`400 VALIDATION_ERROR`，不执行查询副作用。
- 任何跨用户或跨公司的岗位/面试/共享流程引用保持 `404`，不得泄露资源是否存在。

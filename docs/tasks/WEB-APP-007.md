# WEB-APP-007 桌面端岗位横向列表与按需展开

- 状态：`TEST_WRITING`
- 角色：项目管理=主 Agent；独立测试=release_tests；独立实现=company_implementation。
- 用户价值：公司列表在桌面上以岗位为横向行展示，减少纵向卡片占用；多岗位公司默认只显示一个岗位，用户需要时再展开其余岗位。
- 范围：主页公司/岗位列表布局、岗位行默认可见数量、展开/折叠交互、桌面宽度可读性。
- 非范围：后端接口、编辑表单字段、手机端适配验收。
- 依赖：`APP-009`、`WEB-APP-006`。
- 允许修改范围：项目管理仅 `docs/requirements/`、`docs/tasks/`、`docs/acceptance/`；测试仅 `frontend/tests/`、`docs/test-reports/`；实现仅 `frontend/src/`、`docs/implementation-notes/`。

## UI 契约

- 公司仍作为列表聚合单位；每家公司展示一组岗位行。
- 每个岗位是一条横向行，桌面宽度下同一行展示岗位名称、当前阶段/状态、公司共享流程摘要、更新时间和操作入口；不得继续用每岗位一张纵向大卡片作为主列表布局。
- 单岗位公司默认直接展示该岗位行。
- 多岗位公司默认只展示第一条岗位行，并提供可访问的展开/折叠按钮；展开后显示该公司的全部岗位行，折叠后恢复只显示第一条。
- 展开/折叠不发起写请求，不改变搜索、筛选、排序和分页；共享 AI 面、测评、笔试在公司区域只出现一次，不随岗位重复。
- 保留现有编辑、删除和岗位流程入口；岗位行信息应能区分不同岗位及其面试流程。
- 本任务只验收桌面端布局；不新增或维持手机端专门适配断言。

## 验收标准

- [ ] 桌面主页每个岗位在独立横向行内展示，多个岗位不再纵向堆叠为大卡片。
- [ ] 单岗位公司默认看到该岗位行；多岗位公司默认只看到第一条岗位行。
- [ ] 多岗位展开后看到所有岗位行，折叠后回到第一条；操作支持键盘和 `aria-expanded`/`aria-controls`。
- [ ] 展开/折叠没有 POST、PATCH、DELETE 请求，查询/分页状态保持不变。
- [ ] 共享流程摘要只在公司级展示一次，桌面宽度下内容和操作可读。
- [ ] 原有搜索、筛选、排序、编辑、删除和流程数据回归不受影响。

## Agent 交接

- 测试角色先根据公开 UI/HTTP 行为确认 RED，再交实现角色；实现角色不得修改测试。
- 测试角色完成条件：稳定 RED 测试及报告提交。
- 实现角色完成条件：桌面布局实现、必要自检和 READY_FOR_TEST 说明。

## 业务规则与公开契约

- 新增/编辑表单为每个阶段时间提供对应分钟时长输入；有时间无已存时长时回填 60，无时间时对应时长禁用/空置。用户可输入 1～1440 的整数分钟。
- 保存时提交发生变化的字段；新增有时间但未手工改时长仍需产生 60 分钟语义；清空阶段时间时向 API 提交 `null`，本地时长同步清空。
- 编辑回填 API 返回的真实时长，不能用 60 覆盖既存自定义值；失败保留输入并显示对应字段错误；未保存更改确认仍适用。
- 日历与邮件固定 `Asia/Shanghai`；本任务现有表单时间显示仍遵循浏览器本地时区契约，表单应明确标注本地时间，与日历页面的“北京时间”区分。

## 输入、输出与错误行为

- 输入：六阶段开始时间及分钟时长；输出：沿用 `POST/PATCH /api/v1/applications/` 的 snake_case 字段。
- 非法分钟输入阻止提交并定位字段；服务端 `400` 映射对应时长字段；网络错误保留表单；提交中阻止重复请求。

## 验收标准

- [ ] 六阶段时长均能独立输入、回填和编辑，合法值随 POST/PATCH 保存并在重开表单后保持。
- [ ] 新阶段时间获得 60 分钟默认值，已有自定义值不会被覆盖；清空开始时间清空对应时长。
- [ ] 非法时长、服务端字段错误和网络失败有明确且不丢输入的 UI 行为。
- [ ] 现有投递新增/编辑和未保存确认流程回归通过。

## 风险与测试边界

- 测试仅依据 UI 与 HTTP 交互，不阅读生产实现；避免把六阶段写成仅一阶段的镜像测试。

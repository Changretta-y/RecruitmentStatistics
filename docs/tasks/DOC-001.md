# DOC-001 OpenAPI、运行和部署文档

- 状态：`DONE`
- 用户价值：前后端和运维可依据同一份公开契约启动、联调和发布。
- 范围：DRF Spectacular/OpenAPI、Swagger 或 schema 入口、认证/投递接口说明、开发运行和迁移说明。
- 非范围：改变 API 行为、替代自动化测试、生产云平台具体资源创建。
- 依赖：`AUTH-004`、`APP-007`、`SEC-001`、`WEB-APP-004`。
- 允许修改范围：测试 Agent：`backend/tests/`、`frontend/tests/`、`docs/test-reports/`；实现 Agent：`backend/config/`、`backend/apps/`、`frontend/src/`、`README.md` 或 `docs/implementation-notes/`；项目管理 Agent：仅 `docs/requirements/`、`docs/tasks/`、`docs/acceptance/`。

## 业务规则与公开契约

- OpenAPI 文档覆盖注册、登录、刷新、退出、me、投递 CRUD、查询参数、分页、错误结构和 Bearer 安全方案。
- schema 必须能由公开命令生成/校验，且与实际状态码、请求/响应字段一致。
- 文档说明 `uv sync --frozen`、`uv run`、nvm/npm、环境变量、迁移和测试入口；不复制会漂移的版本事实。
- 不在文档中写入真实密钥、Token、数据库密码或生产地址。

## 验收标准

- [x] OpenAPI 入口可访问或可生成，所有公开接口和错误码均有描述。
- [x] schema 校验通过，抽样请求响应与实现一致。
- [x] 新环境启动、迁移、后端测试、前端测试/构建和 E2E 命令有清晰说明。
- [x] 文档说明范围外功能，避免把未来扩展当作本期契约。
- [x] 测试先证明文档/schema 缺口，再由实现和独立复测完成。

## 风险与测试边界

- 文档测试不应只检查文件存在，至少验证 schema 可生成并包含关键路径。
- 版本号仍以环境规范和锁文件为准。

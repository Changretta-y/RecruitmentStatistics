## 业务规则与公开契约

### 1. 唯一状态来源

岗位的 `application_status` 是唯一可编辑、可筛选、可展示的业务状态，规范值固定为：

| 值 | 精确展示名 | 业务含义 |
|---|---|---|
| `applied` | 投递 | 已提交投递，尚未归入其他状态 |
| `assessment` | 测评 | 测评阶段 |
| `written_test` | 笔试 | 笔试阶段 |
| `first_interview` | 一面 | 第一轮面试 |
| `second_interview` | 二面 | 第二轮面试 |
| `other_interview` | 其他轮次 | 三面、复试或其他自定义面试轮次 |
| `hr_interview` | HR面 | HR 面试 |
| `rejected` | 拒绝 | 企业拒绝或流程终止 |

新建岗位缺省为 `applied`。`in_progress`、`offer`、`withdrawn` 和其他未知值均不是新契约值，写入时必须被拒绝。

`current_stage` 不再是第二个业务状态：为兼容旧客户端可以继续出现在公司聚合/共享响应中，但必须是主岗位 `application_status` 的只读等值投影；不得由最新日程、固定优先级或自定义面试名称派生，也不得被客户端写入。前端不得把它作为另一个标签、选择器或筛选条件。

AI 面可以继续出现在 `shared_stages` 和日历/提醒日程中，但不是业务状态选项；仅填写、修改或清空任何共享阶段/面试时间，不自动改变业务状态。修改业务状态不改变任何时间或时长。

### 2. API 契约

- `POST /api/v1/applications/`、`PATCH /api/v1/applications/{company_id}/` 中，嵌套 `positions[*].application_status` 只接受规范八值；成功响应的所有岗位返回规范值。
- 旧 flat 写入路径若仍由现有客户端使用，其 `application_status` 同样只接受规范八值，并同步到主岗位；不允许通过 flat `current_stage` 写入状态。
- `GET` 公司列表/详情的岗位状态、兼容顶层状态以及 `GET /api/v1/sharing/users/{user_id}/applications/` 的只读状态必须使用同一规范值。顶层兼容投影与主岗位不一致视为契约错误。
- `/api/v1/applications/` 的 `application_status` 支持单值、逗号分隔或重复参数，值域仅为规范八值；按公司下任一岗位匹配，分页单位仍为公司。未知/旧值返回 `400 VALIDATION_ERROR`，错误详情指向 `application_status`。
- 应用列表的旧 `stage` 参数不再表示业务状态或日程是否填写；新契约要求传入该参数返回 `400 VALIDATION_ERROR`，详情指向 `stage`。日历接口和邮件汇总内部使用的事件 `stage` 保持原契约，不在本任务中改名。
- 未认证仍返回 `401`；不存在或跨用户资源仍返回 `404`；状态校验失败返回 `400` 且不产生部分写入。原有岗位、共享流程、面试子资源、分页和数据隔离行为不回归。APP-009 中仅断言旧 `in_progress`/`offer` 或日程派生 `current_stage` 的断言属于已废止测试契约，必须改为本任务八值和等值兼容投影后继续验证同一业务行为。

### 3. 历史值迁移

实现 Agent 必须提供可审查的数据库迁移或等价迁移处理，并在实现说明中记录每种旧值的迁移数量及规则：

| 旧值/旧派生阶段 | 新值 |
|---|---|
| `applied` | `applied` |
| `rejected` | `rejected` |
| `in_progress` + 测评日程 | `assessment` |
| `in_progress` + 笔试日程 | `written_test` |
| `in_progress` + 一面日程 | `first_interview` |
| `in_progress` + 二面日程 | `second_interview` |
| `in_progress` + 三面/自定义面试日程 | `other_interview` |
| `in_progress` + HR 面日程 | `hr_interview` |
| `in_progress` + 仅 AI 面或无可映射流程 | `applied` |
| `offer`、`withdrawn` | `rejected` |

岗位名称、备注、投递时间、共享流程、面试记录及其时长必须保留。迁移后公开状态不得出现旧值；日历/提醒仍可按原日程事件工作。

### 4. 前端公开行为

- `ApplicationStatus` 类型和所有状态选项只包含八个规范值，展示顺序固定为“投递、测评、笔试、一面、二面、其他轮次、HR面、拒绝”。
- `ApplicationForm.vue` 每个岗位只提供一个“业务状态”选择器；不提供独立的“当前阶段/面试状态”选择器。状态可在新增、编辑中回填、修改和保存。
- `ApplicationsView.vue` 每个岗位只渲染一个业务状态标签；公司折叠首岗位、展开的其他岗位和 `PositionFlowCard.vue` 使用同一映射。不能用 `currentStage` 覆盖或替换已保存的 `applicationStatus`。
- 状态筛选只提供规范八值，label 使用精确展示名；新的 URL/API 请求只发送 `application_status`，不发送 `stage` 业务状态筛选。刷新、返回、翻页、搜索和其他查询条件保留既有行为。
- 共享页面显示的状态使用同一精确映射；共享仍只读，不增加编辑入口，不泄露备注或其他岗位私有数据。

## 输入、输出与错误行为

### 合法输入

```json
{
  "positions": [
    {"position_name": "后端开发", "application_status": "second_interview"}
  ]
}
```

成功创建仍返回 `201`，成功 PATCH 返回 `200`；返回体中的岗位状态为 `second_interview`，兼容顶层 `application_status`/`current_stage`（若存在）必须与主岗位相同。

### 非法输入

- `application_status` 为 `in_progress`、`offer`、`withdrawn`、`ai_interview`、中文展示名或未知值：`400 VALIDATION_ERROR`，详情指向对应岗位状态路径或 `application_status`。
- 应用列表的 `application_status` 包含非法/旧值，或请求 `/applications/` 携带 `stage`：`400 VALIDATION_ERROR`，不执行查询副作用。
- 旧状态迁移、状态 PATCH、嵌套岗位更新失败时，其他岗位、流程和时间不得被部分修改。

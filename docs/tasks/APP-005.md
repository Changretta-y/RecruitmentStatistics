# APP-005 搜索、筛选与排序

- 状态：`DONE`
- 用户价值：用户能快速定位公司和岗位，并按进度和时间查看投递记录。
- 范围：列表 `search`、`application_status`、`stage`、投递时间范围和白名单 `ordering`。
- 非范围：全文检索扩展、统计报表、前端查询组件。
- 依赖：`APP-004`、`APP-001`。
- 允许修改范围：测试 Agent：`backend/tests/`、`docs/test-reports/`；实现 Agent：`backend/apps/`、`backend/config/`、`docs/implementation-notes/`；项目管理 Agent：仅 `docs/requirements/`、`docs/tasks/`、`docs/acceptance/`。

## 业务规则与公开契约

- `search` 对公司名和岗位名做模糊匹配；查询仍先限定当前用户。
- `application_status` 按五种状态过滤；`stage` 支持 `ai_interview`、`written_test`、`first_interview`、`second_interview`、`third_interview`、`hr_interview`，只筛选该时间是否已填写。
- `application_time_after`、`application_time_before` 接受 ISO 8601 时间范围。
- `ordering` 仅允许 `created_at`、`updated_at`、`application_time` 及六个阶段字段，前缀 `-` 表示倒序；默认 `-updated_at,-id`。
- 未知筛选或排序字段返回统一 `400 VALIDATION_ERROR`，不能把任意输入直接传给 ORM。

## 验收标准

- [x] 公司名和岗位名搜索均命中，且不会命中其他用户数据。
- [x] 状态、每个阶段已填写/未填写和投递时间范围筛选正确。
- [x] 全部白名单排序字段正/倒序有效，默认排序稳定。
- [x] 非法状态、阶段、时间或 ordering 被拒绝且错误结构稳定。
- [x] 组合筛选与分页可同时使用；测试先 RED 后实现。

## 风险与测试边界

- 空时间的排序 null 位置必须固定并写入测试报告；不得依赖数据库偶然默认。
- `current_stage` 是派生展示字段，不能作为可注入的 ORM 排序字段。

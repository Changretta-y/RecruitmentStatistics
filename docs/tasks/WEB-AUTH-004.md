# WEB-AUTH-004 认证页面宽度与注册页返回登录入口

- 状态：`DONE`
- 用户价值：登录和注册表单在桌面端有舒适的阅读与输入宽度，用户进入注册页后可直接返回登录页。
- 范围：登录页与注册页认证容器的响应式宽度；注册页“返回登录”入口及其路由行为；相关前端组件测试。
- 非范围：认证 API、字段校验规则、Token 行为、整体品牌视觉重做、其他业务页面布局。
- 依赖：`WEB-AUTH-003`。
- 允许修改范围：测试 Agent：`frontend/tests/`、`tests/e2e/`、前端测试配置/测试依赖、`docs/test-reports/`；实现 Agent：`frontend/src/`、前端运行时配置/依赖、`docs/implementation-notes/`；项目管理 Agent：`docs/requirements/`、`docs/tasks/`、`docs/acceptance/`。

## 业务规则与公开 UI 契约

- 登录页和注册页应复用一致的认证容器宽度规则。
- 在视口宽度不小于 768px 时，认证卡片目标宽度为 `560px`；允许边框、盒模型或 UI 组件产生不超过 2px 的测量误差。
- 在视口宽度小于 768px 时，认证卡片应随视口收缩，左右至少保留 `16px` 可视间距，页面不得因认证卡片产生横向滚动。
- 注册页必须提供可见、可聚焦且语义明确的“返回登录”入口；用户激活后导航至 `/login`。
- 返回登录入口不提交注册表单，不改变既有注册成功自动跳转登录页的行为。

## 输入、输出与错误行为

- 输入：用户直接访问 `/login` 或 `/register`，以及在注册页点击/键盘激活“返回登录”。
- 输出：桌面端显示更宽的认证卡片；窄屏保持完整可见；返回入口导航到 `/login`。
- 错误行为：返回入口不得触发注册请求；不得依赖浏览器历史记录，直接访问注册页时也必须可用。

## 验收标准

- [x] 1280px 宽视口下，登录与注册认证卡片的可见宽度均为 `560px ± 2px`，且两页宽度一致。
- [x] 375px 宽视口下，登录与注册页面无横向溢出，认证卡片左右各至少保留 `16px` 可视间距。
- [x] 注册页展示可通过可访问名称“返回登录”查询的链接或按钮，并支持键盘聚焦。
- [x] 激活“返回登录”后进入 `/login`，且不触发注册 API 请求。
- [x] 原有登录、注册提交、校验、错误展示和注册成功跳转行为的相关回归测试通过。

## 风险与测试边界

- 宽度测试应通过公开 DOM 与渲染样式观测，避免断言私有组件实现或具体 class 名。
- jsdom 对真实布局支持有限；组件测试可验证公开样式契约，若现有 E2E 环境可用则补充真实视口尺寸断言。
- “返回登录”使用路由目标断言，不读取或分析生产实现代码。

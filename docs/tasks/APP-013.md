# APP-013 复用同名公司时补齐空招聘链接

- 状态：PLANNED
- 用户价值：当其他用户已经登记同一公司但没有招聘网站链接时，当前用户通过插件或旧 flat 接口提交有效链接后，自己的投递和公司公共信息都能显示该链接。
- 范围：修复旧 flat `POST /api/v1/applications/` 复用既有全局公司时的招聘链接补齐规则，并验证跨用户公开公司链接投影。
- 非范围：不覆盖已有非空公司链接、不改变岗位状态/流程、公司权限模型、前端链接展示或插件匹配规则。
- 依赖：APP-012 全局公司目录与旧 flat 兼容契约；WEB-APP-013 公司名链接展示。
- 允许修改范围：项目管理仅 `docs/tasks/`、`docs/acceptance/`；测试仅 `backend/tests/`、`docs/test-reports/`；实现仅 `backend/apps/`、`backend/config/`、`backend/manage.py`、`docs/implementation-notes/`。

## 业务规则与公开契约

1. 旧 flat 创建提交 `company_name`、`application_url` 时，若规范化同名 `Company` 已存在且 `recruitment_url` 为空，服务端可将该有效 URL 补写为公司的全局招聘网站。
2. 若既有公司已有非空 `recruitment_url`，任何其他用户或旧客户端提交的 URL 都不能覆盖它。
3. 复用公司创建投递聚合后，响应中的 `recruitment_url`、`company.recruitment_url` 和后续列表/详情投影必须一致；公司其他用户可看到公开链接，但岗位、备注和状态仍按用户隔离。
4. 空字符串、非法 URL 或未提供 URL 不得把公司链接写成空值；原有字段级错误和事务原子性保持不变。

## 验收标准

- [ ] 用户 A 先创建无招聘链接的公司，用户 B 以同名公司和有效旧 flat `application_url` 投递后，公司链接被补齐且 B 的响应/列表可见。
- [ ] 既有非空公司链接不会被另一个用户提交的不同 URL 覆盖，A/B 看到同一个原链接。
- [ ] 无效、空或缺失 URL 不会写入空链接或产生部分投递数据。
- [ ] 用户岗位与公司链接公开投影、权限隔离及 APP-012 相关回归通过。
- [ ] 测试 Agent 先提交稳定 RED；实现 Agent 提交 READY_FOR_TEST；测试 Agent 独立 TEST_PASSED；PM 最后验收 DONE。

## 风险与测试边界

- 测试仅通过认证 HTTP API 和响应数据验证，不读取生产实现；至少覆盖两个用户、同名公司、空/非空 URL 和非法 URL。
- 全局公司链接是公开元数据，岗位私有字段不得因补链接而跨用户泄露。

# WEB-APP-004 删除确认、空状态与异常状态

- 状态：`DONE`
- 用户价值：删除操作防误触，列表在删除、网络异常和记录消失时保持可理解且一致。
- 范围：删除确认对话框、DELETE 调用、当前页回退、成功刷新、404/403/500/网络错误处理。
- 非范围：后端删除权限、软删除、审计和离线缓存。
- 依赖：`WEB-APP-002`、`WEB-APP-003`、`APP-007`。
- 允许修改范围：测试 Agent：`frontend/tests/`、`tests/e2e/`、`docs/test-reports/`；实现 Agent：`frontend/src/`、`docs/implementation-notes/`；项目管理 Agent：仅 `docs/requirements/`、`docs/tasks/`、`docs/acceptance/`。

## UI 契约

- 删除前对话框展示公司名和岗位；取消不发送请求。
- 成功删除后重新查询当前页；删除最后一条且当前页大于 1 时页码减 1；显示成功提示。
- 404 提示记录不存在/已删除并刷新；403 提示无权操作；500 不暴露后端堆栈；网络错误保留查询并提供重试。
- 空数据提供新增入口，无结果提供重置筛选。

## 验收标准

- [x] 取消删除无副作用，确认删除发送正确 ID 并更新列表。
- [x] 当前页最后一条删除时页码回退规则正确。
- [x] 空状态、无结果、404、403、500 和网络失败均有可观察 UI。
- [x] 错误提示不包含 Token、密码或堆栈。
- [x] 测试先 RED，并覆盖成功和边界后独立复测。

## 风险与测试边界

- 删除确认应可键盘和屏幕阅读器操作；具体组件库实现不改变行为契约。
- 级联删除用户不属于前端任务。

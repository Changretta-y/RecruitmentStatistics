# EXT-ROUTE-003 插件查看与搜索已投递公司

- 状态：DONE
- 用户价值：用户在浏览器插件录入当前投递前，可以查看并搜索自己已经投递过的公司及岗位，避免重复投递或误更新。
- 范围：插件登录后的已投递公司列表、公司名搜索、岗位摘要、刷新与加载/错误状态；复用当前用户应用列表 API。
- 非范围：不读取其他用户或共享页面数据，不改变保存匹配规则、后端数据模型、主站搜索、公司目录或插件页面采集逻辑。
- 依赖：EXT-AUTH-001 登录与 token 刷新；EXT-ROUTE-002 插件投递匹配；APP-009/APP-012 应用列表公开响应。
- 允许修改范围：项目管理仅 `docs/tasks/`、`docs/acceptance/`；测试仅 `tests/e2e/`、`frontend/tests/`、`docs/test-reports/`；实现仅 `frontend/src/browser-extension/`、生成的 `artifacts/recruitment-capture-extension-v0.1.0.zip`、`docs/implementation-notes/`。

## 业务规则与公开契约

1. 登录成功并进入采集视图后，插件显示“已投递公司”区域，读取当前登录账号的 `/api/v1/applications/` 分页结果。
2. 列表按公司聚合去重；每项显示公司名和该公司当前用户已登记的岗位名称。不得显示其他用户岗位、备注、私有流程或用户 ID。
3. 搜索框按公司名或岗位名不区分大小写模糊过滤，输入为空显示全部当前用户公司；搜索不触发写入操作。
4. 支持手动刷新；加载中、空列表、未登录/认证失效、网络失败均有明确状态，失败不能清除当前已展示的采集表单。
5. 列表请求使用现有认证客户端并处理 token 刷新；退出登录后列表和搜索内容清空。

## 输入、输出与错误行为

- 输入：已登录用户打开插件、输入公司或岗位关键字、点击刷新。
- 输出：已投递公司列表、匹配岗位摘要和结果计数；点击当前采集不改变原有保存流程。
- 未认证：不请求应用列表，继续显示登录视图。
- HTTP 401：按现有认证失效处理并提示重新登录；网络错误显示重试入口。
- 空结果：显示“暂无已投递公司”或“没有匹配结果”，不伪造记录。

# APP-014 用户隔离的提示词管理 API

- 状态：RED_CONFIRMED
- 用户价值：用户可以保存和复用自己的面试/求职提示词，数据互不串用。
- 范围：新增认证用户提示词的预设、列表搜索、新增、修改、删除 API；首次访问为用户创建预设提示词。
- 非范围：公共提示词市场、跨用户共享、版本历史、AI 调用。
- 依赖：现有 JWT 登录与 DRF API。
- 允许修改范围：项目管理仅 `docs/tasks/`、`docs/acceptance/`；测试仅 `backend/tests/`、`tests/e2e/`、`docs/test-reports/`；实现仅 `backend/apps/`、`backend/config/`、`docs/implementation-notes/`。

## 业务规则与公开契约

- `GET /api/v1/prompts/` 仅返回当前登录用户的提示词；首次访问自动创建一组预设提示词。
- 支持 `search` 查询参数，匹配标题或内容，不区分大小写；返回 `{count,page,page_size,total_pages,next,previous,results}`。
- `POST /api/v1/prompts/` 接受 `{title,content}`，服务端绑定当前用户；标题 1-100 字符，内容 1-10000 字符，去除首尾空白后不能为空。
- `PATCH /api/v1/prompts/{id}/` 可修改标题或内容；`DELETE` 删除当前用户自己的记录并返回 204。
- 其他用户的 ID 对当前用户表现为 404，不能读取、修改或删除。
- 每条记录返回 `id,title,content,is_preset,created_at,updated_at`；不接受客户端提交的 user/owner 字段。
- 预设提示词至少包含“自我介绍”“项目经历深挖”“行为面试 STAR”三类可直接复制的内容；预设同样允许用户修改和删除，删除后不因刷新重新出现。

## 验收标准

- [ ] 首次登录用户能获取预设提示词，且另一用户看不到这些记录。
- [ ] 列表搜索、新增、修改、删除和字段校验符合契约。
- [ ] 越权访问返回 404，不能改变他人数据。
- [ ] 数据库迁移可在测试数据库执行，现有认证/投递 API 回归不受影响。

## 风险与测试边界

- 测试必须使用两个认证用户验证隔离；不得读取生产实现代码来构造断言。
- 预设初始化需要覆盖删除后不重建的行为。

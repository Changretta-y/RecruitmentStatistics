# DB-001 Django 数据与 PostgreSQL 迁移基线

- 状态：`DONE`
- 用户价值：后续用户和投递数据有可重复创建、迁移和测试的真实 PostgreSQL 基线。
- 范围：Django/DRF 应用注册、PostgreSQL 配置入口、测试数据库隔离、迁移命令和认证依赖的最小接线。
- 非范围：用户注册接口、JWT 业务行为、投递模型字段、前端页面和生产部署。
- 依赖：`BASE-ENV-001`。
- 允许修改范围：测试 Agent 仅可改 `backend/tests/`、`docs/test-reports/`；实现 Agent 可改 `backend/apps/`、`backend/config/`、`backend/manage.py`、后端运行时依赖和 `docs/implementation-notes/`；项目管理 Agent 仅改 `docs/requirements/`、`docs/tasks/`、`docs/acceptance/`。

## 业务规则与公开契约

- 后端依赖通过 `uv` 锁定；开发、测试、迁移命令均通过 `uv run` 执行。
- 默认开发数据库来自 `DATABASE_URL`；测试必须使用独立数据库配置，禁止连接开发或生产库。
- `manage.py check`、`makemigrations --check`、`migrate` 可在全新环境重复执行；迁移文件纳入版本控制。
- Django、DRF、JWT 黑名单所需应用和中间件必须可被公开命令验证，但本任务不要求业务接口可用。

## 输入、输出与错误行为

- 输入：全新检出仓库、冻结依赖和可用 PostgreSQL。
- 输出：`uv run python manage.py check` 成功；`uv run python manage.py migrate` 成功；测试数据库不会复用开发数据库。
- 缺少 `DATABASE_URL`、数据库不可连接或迁移漂移：命令以非零状态失败并给出可定位错误，不静默切换到 SQLite。

## 验收标准

- [x] Django/DRF/JWT 黑名单依赖和应用注册可由配置检查公开验证。
- [x] 使用项目环境执行 `check`、`migrate`、迁移漂移检查均成功。
- [x] 测试配置指向独立数据库，且一次测试不会修改开发数据。
- [x] 迁移文件可在空数据库完整执行并可重复检查。
- [x] 测试先证明至少一项基线契约缺失，再由实现完成并独立复测。

## 风险与测试边界

- PostgreSQL 的时区和约束行为不能用 SQLite 替代；测试 Agent 应验证数据库类型和连接隔离。
- 本任务不验收任何注册、登录或投递业务行为。

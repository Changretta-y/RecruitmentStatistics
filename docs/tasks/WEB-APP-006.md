# WEB-APP-006 公司多岗位流程表单与列表展开

- 状态：`PLANNED`
- 角色：项目管理=主 Agent；独立测试=release_tests（本任务仅测试角色）；独立实现=company_implementation。
- 用户价值：新增或编辑公司记录时能维护多个投递岗位和流程；主页能展开公司查看每个岗位的完整流程。
- 范围：新增/编辑表单的岗位增删改、公司级 AI 面/测评/笔试、岗位级多面试编辑；公司列表分组展开及流程展示。
- 非范围：后端数据模型/API、日历与邮件适配、跨用户分享。
- 依赖：`APP-009`、`WEB-APP-001`、`WEB-APP-002`、`WEB-APP-003`、`WEB-APP-005`。
- 允许修改范围：项目管理 Agent 仅 `docs/requirements/`、`docs/tasks/`、`docs/acceptance/`；测试 Agent 仅 `frontend/tests/`、`tests/e2e/`、`docs/test-reports/`；实现 Agent 仅 `frontend/src/`、`docs/implementation-notes/`。共享配置变更由项目管理 Agent 排序。

## UI 契约

- 新增/编辑页以公司为一条主记录，至少提供一个岗位；用户可添加、编辑和移除岗位。岗位字段（岗位名、状态、投递时间、备注）分别编辑和保存。
- 公司级流程区提供 AI 面、测评、笔试各一个时间入口；编辑多个岗位时仍只有一组公司级入口。清空日期提交 `null`。
- 每个岗位独立提供可重复添加的面试环节；面试名称必填，时间/时长按 API 契约编辑。用户可编辑或删除指定面试记录。
- 列表每家公司显示一行；公司下有多个岗位时提供可访问的展开/折叠操作。展开后逐个显示该公司的所有岗位投递记录和流程：共享 AI 面/测评/笔试在公司区域清晰可见，各岗位的面试按该岗位分别显示。
- 仅有一个岗位的公司维持直接可读的行展示；多岗位行展示岗位数量或摘要。展开状态切换不改变查询、分页、排序，不发起写请求。
- 新增/编辑保存期间禁用重复提交；失败保留所有岗位和流程的输入并显示可理解错误；成功后列表显示服务端保存的嵌套数据。未保存退出确认继续生效。
- 删除公司沿用现有确认流程；确认说明包含公司名及岗位数，成功后公司整组消失。

## 输入、输出与错误行为

- 表单读写 `APP-009` 的公司嵌套对象与子资源 API；不得把公司级共享流程复制到岗位面试中，也不得因岗位表单局部编辑覆盖另一岗位。
- 服务端字段错误映射到公司、岗位或具体面试输入；网络错误保留完整表单状态并提供重试。
- 展开/折叠控件支持键盘操作，并通过 `aria-expanded` 与关联内容提供状态。

## 验收标准

- [ ] 新增页可创建含多个岗位、共享阶段和不同面试流程的公司；刷新后所有内容正确回显。
- [ ] 编辑页可新增/编辑/移除岗位和任一面试，改动仅影响目标对象；共享阶段只出现一次。
- [ ] AI 面、测评、笔试各自只有一个公司级控件；一个岗位可添加多个、名称相同的面试记录。
- [ ] 多岗位公司主页可展开并看到所有岗位记录及流程，折叠后回到单行；单岗位公司显示符合契约。
- [ ] API 校验错误、网络失败、重复提交和删除确认保持已有可靠交互且不丢输入。
- [ ] 旧有分页、搜索、筛选、排序、状态展示和未保存确认回归通过。

## 业务规则与公开契约

- 六个字段名、对应阶段、默认 60 分钟、既有自定义时长保留、1～1440 分钟整数范围及时间清空联动遵循需求第 2 节。
- 对既有数据执行迁移：有阶段时间则该阶段时长 60，无时间则 `null`；迁移后旧客户端只提交阶段时间仍可用。
- `POST /api/v1/applications/` 和 `PATCH /api/v1/applications/{id}/` 接受可编辑时长；所有返回完整记录的既有接口输出时长字段。只提交时长不改变开始时间；只清空开始时间自动清空时长；未提交其他字段保持不变。
- 客户端不能提交 `user`、`current_stage` 等只读字段改变归属或阶段派生；用户隔离沿用既有投递 API。

## 输入、输出与错误行为

- 合法创建返回 `201`，合法 PATCH 返回 `200` 和含六个时长字段的完整记录。
- 新设开始时间而无旧时长时使用 60；已有自定义时长在仅修改开始时间时保留；无开始时间时长必须为 `null`；清空时间时自动清空时长。同一请求清空时间却提交非空时长返回 `400`。
- 零、负数、小数、字符串、超过 1440，或在无时间阶段单独提交非空时长，返回 `400 VALIDATION_ERROR` 并标记对应字段；未认证 `401`，跨用户详情/PATCH `404`。

## 验收标准

- [ ] 六阶段分别设置开始时间和时长后，创建/详情/列表/PATCH 返回正确值，阶段之间互不覆盖。
- [ ] 历史记录迁移后有时间的阶段为 60 分钟、空时间阶段为 `null`；旧客户端只送时间仍能得到默认时长。
- [ ] PATCH 只改一个时长时其他字段不变，清空时间联动清空时长；无时间不能单独设置时长。
- [ ] 范围、类型与权限错误的状态码和字段错误明确，失败不写入。

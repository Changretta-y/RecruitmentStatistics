## 业务规则与公开契约

- `GET /api/v1/calendar/events/?start=YYYY-MM-DD&end=YYYY-MM-DD`；开始日期包含、结束日期不包含，按固定 `Asia/Shanghai` 时区换算成时间窗口，跨度 1～42 天。
- 响应 `200`：`{"timezone":"Asia/Shanghai","start":"2026-09-01","end":"2026-10-01","events":[...]}`；事件包含 `application_id`、`company_name`、`position_name`、`stage`、`start_at`、`end_at`、`duration_minutes`。
- 阶段代码依次为 `ai_interview`、`written_test`、`first_interview`、`second_interview`、`third_interview`、`hr_interview`；排序按开始瞬间、投递 ID、该阶段次序。
- 对 `[start_at,end_at)` 与查询窗口相交的本人六阶段安排各返回一条完整事件，不截断原起止时间；由 UI 按日期绘制片段。即使事件数量大于 100 也全部返回，不能复用投递列表分页。
- 无时间不生成事件；终态投递仍保留已设置事件；删掉投递后事件消失。

## 输入、输出与错误行为

- 缺少参数、日期格式错误、结束不大于开始或跨度超过 42 天，返回 `400 VALIDATION_ERROR` 并标记参数；未认证返回 `401`。成功无事件返回空数组。
- 不能通过日期范围、ID 或响应元数据看到其他用户的记录。

## 验收标准

- [ ] 范围内、跨入范围和恰好在午夜结束的事件遵守左闭右开边界，六阶段各自可见。
- [ ] 事件按稳定顺序输出，字段及起止时刻正确；超过 100 条仍完整，无安排为空数组。
- [ ] 非法范围、未认证、跨用户数据隔离有可观察正确结果。
- [ ] 阶段清空/记录删除后不再出现，投递终态不自动移除事件。

- 关注 SQL 查询次数和输出体量，但不改变第一期最多 42 天完整返回契约。

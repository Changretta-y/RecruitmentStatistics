# APP-003 本人列表/详情与数据隔离

- 状态：`DONE`
- 用户价值：用户能查看自己的投递数据，同时无法通过猜 ID 或请求参数访问他人记录。
- 范围：`GET /api/v1/applications/`、`GET /api/v1/applications/{id}/`、认证和 QuerySet 用户隔离。
- 非范围：分页参数、搜索筛选排序、修改和删除。
- 依赖：`APP-002`、`AUTH-002`。
- 允许修改范围：测试 Agent：`backend/tests/`、`docs/test-reports/`；实现 Agent：`backend/apps/`、`backend/config/`、`docs/implementation-notes/`；项目管理 Agent：仅 `docs/requirements/`、`docs/tasks/`、`docs/acceptance/`。

## 业务规则与公开契约

- 列表和详情均需 Bearer Access Token；列表只从 `request.user` 的 QuerySet 读取。
- 默认排序为 `updated_at DESC, id DESC`；响应使用分页结构，即使默认只返回一页。
- 他人记录的详情、后续更新或删除均必须表现为 `404 NOT_FOUND`，不能泄露记录存在性。
- 不接受 query/body 中的 user 过滤来绕过服务端归属条件。

## 输入、输出与错误行为

- 未认证：`401`。
- 不存在或不属于当前用户的详情：`404 NOT_FOUND`。
- 列表成功：`200`，含 `count`、`page`、`page_size`、`total_pages`、`next`、`previous`、`results`。

## 验收标准

- [x] 用户列表只返回本人记录，另一用户记录不可见。
- [x] 本人详情返回完整序列化记录和派生当前阶段。
- [x] 猜测他人 ID 返回 404，且不会改变响应中可观察的存在性信息。
- [x] 未认证列表/详情均为 401。
- [x] 测试覆盖两个用户、空列表和不存在 ID，并先形成 RED。

## 风险与测试边界

- 分页精确参数由 `APP-004` 定义；此任务只验证默认列表容器和隔离。
- 必须用公开 HTTP 输入输出测试，不导入 ViewSet 或读取实现内部结构。

# SEC-001 安全配置、错误处理与日志脱敏

- 状态：`DONE`
- 用户价值：系统在开发、测试和生产边界上不泄露密码、Token、密钥或调试堆栈。
- 范围：环境变量配置、CORS/安全头、统一异常响应、请求日志脱敏、认证/业务限流入口和生产 DEBUG 约束。
- 非范围：第三方 WAF、完整操作审计、漏洞扫描平台、HttpOnly Cookie 迁移。
- 依赖：`AUTH-004`、`APP-007`、`WEB-AUTH-003`。
- 允许修改范围：测试 Agent：`backend/tests/`、`frontend/tests/`、`docs/test-reports/`；实现 Agent：`backend/config/`、`backend/apps/`、`frontend/src/`、运行时配置和 `docs/implementation-notes/`；项目管理 Agent：仅 `docs/requirements/`、`docs/tasks/`、`docs/acceptance/`。

## 业务规则与公开契约

- `DJANGO_SECRET_KEY`、`DATABASE_URL`、`CORS_ALLOWED_ORIGINS` 等敏感配置来自环境变量；`.env` 不提交。
- 生产 `DEBUG=false`，CORS 不允许任意来源；启用 HTTPS 场景的安全响应头和合理的 Referrer/Content-Type 策略。
- 统一错误响应不包含 Python 堆栈、SQL、密码、完整 Authorization 或 Token。
- 登录/注册可有基于 IP/用户名的限流入口，触发时为稳定 429；不能影响测试环境的确定性。

## 验收标准

- [x] 缺少必需敏感配置时启动/检查失败而非使用危险默认值。
- [x] 生产配置不暴露 DEBUG、密钥、密码、Token 和异常堆栈。
- [x] 日志能记录方法/路径/状态/耗时和用户/记录 ID（如可得），同时脱敏认证头和凭据。
- [x] CORS、安全头和限流行为有公开配置或接口测试证据。
- [x] 测试先证明至少一项泄露/危险默认缺失，再独立复测。

## 风险与测试边界

- 不把安全检查实现成只读源代码断言；优先通过配置、响应头、错误响应和日志输出观察。
- 生产部署平台细节由 `REL-001` 演练验证。

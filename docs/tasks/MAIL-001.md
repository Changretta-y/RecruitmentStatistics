## 业务规则与公开契约

- 每位认证用户最多一份设置：`recipient_email`、`daily_time`（北京时间、24 小时 `HH:mm`）、`enabled`、`verified`、`timezone`（固定 `Asia/Shanghai`）、只读 `last_delivery`（最近发送日期/状态，尚未发送为 `null`）；默认邮箱未配置、时间未配置、关闭、未验证。
- `GET/PATCH /api/v1/notification-settings/` 只操作本人设置。PATCH 可以独立修改邮箱、时间、开关；开启必须有合法收件地址、验证已通过及合法时间。修改邮箱立即使新地址未验证并关闭推送，旧地址不再接收。
- `POST /api/v1/notification-settings/verification/` 仅对待验证地址发一次性、限时验证邮件；`POST /api/v1/notification-settings/verify/` 消费令牌后标记当前待验证地址已验证。令牌不能验证旧地址或他人的设置。重复申请需限制频率，避免邮件滥用。
- 验证邮件由应用服务端使用平台统一 SMTP 配置发送。公开响应可以展示设置中的邮箱及验证状态给本人；令牌、SMTP 凭据不能回显或写入日志。SMTP 配置缺失或连接失败时不返回成功申请，不改变验证状态，返回可观察错误。

## 输入、输出与错误行为

- 合法 GET/PATCH 返回 `200`；验证邮件申请成功返回 `202`；有效令牌验证成功返回 `200`。所有认证接口未登录 `401`。
- 非法邮箱、时间格式、不完整设置下开启返回字段级 `400 VALIDATION_ERROR`；令牌过期/无效/已用返回可理解错误；发送验证邮件失败不标记已验证，并可重试。

## 验收标准

- [ ] 用户只能读写本人设置，新用户默认关闭；邮件和时间均合法且地址已验证后才能开启。
- [ ] 改地址撤销原验证并停止旧地址发送资格；新地址验证前不能开启；令牌一次性、限时且绑定用户和地址。
- [ ] 非法字段、未登录、过期/重放令牌、SMTP 配置缺失和发送失败有正确公开错误且不泄密；发送失败不标记已验证。
- [ ] 验证申请有频率限制，无法借接口大量发信。

## 风险与测试边界

- 第一版收件地址验证令牌 TTL 24 小时；同用户同地址每小时最多申请 3 次，超过返回 `429` 且不发邮件。测试与实现以此为固定契约。
- 测试使用邮件测试后端/公开捕获机制，不要求真实外发；黑盒声明适用。

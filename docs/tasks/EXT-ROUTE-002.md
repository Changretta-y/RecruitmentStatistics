# EXT-ROUTE-002 修复插件同公司多岗位覆盖

- 状态：PLANNED
- 用户价值：浏览器插件录入同一公司的不同岗位时，每个岗位都能独立保存，不会因共用招聘链接而覆盖已有岗位。
- 范围：修复插件保存前的公开匹配规则及可加载交付包；补充同公司多岗位黑盒回归。
- 非范围：不改变后端公司聚合模型、岗位流程、认证、页面字段提取或公司招聘链接本身。
- 依赖：APP-009/APP-012 的同公司多岗位追加契约；EXT-ROUTE-001 插件构建与 URL 兼容基线。
- 允许修改范围：项目管理仅 `docs/requirements/`、`docs/tasks/`、`docs/acceptance/`；测试仅 `tests/e2e/`、`frontend/tests/`、`docs/test-reports/`；实现仅 `frontend/src/browser-extension/`、生成的 `artifacts/recruitment-capture-extension-v0.1.0.zip`、`docs/implementation-notes/`。

## 业务规则与公开契约

1. 插件保存匹配的主身份是规范化后的“公司名 + 岗位名”。两者都填写时，必须先按该组合匹配。
2. 公司招聘链接或岗位页面 URL 不能作为跨岗位覆盖的唯一依据。同一公司不同岗位即使使用相同 `application_url`，也必须按新岗位创建/追加。
3. 同一公司同一岗位再次录入时，才允许命中已有岗位并 PATCH；其链接变化可以更新该岗位的链接。
4. 新岗位创建请求继续使用现有公开 API/字段，后端返回的公司聚合应同时保留旧岗位和新岗位。
5. 若公司名或岗位名缺失，插件继续使用现有人工修正/错误提示；不得为了避免覆盖而静默选择其他岗位。

## 输入、输出与错误行为

- 输入：已有公司岗位记录，当前插件填写相同公司名、不同岗位名，且当前页面链接与已有记录相同或属于同一招聘入口。
- 期望输出：预览显示新建操作；确认时发送 `POST /api/v1/applications/`，不发送旧岗位 `PATCH`；返回结果包含原岗位与新岗位。
- 同公司同岗位输入：预览可显示更新，确认时只 PATCH 目标岗位对应记录。
- 匹配存在多条相同公司+岗位记录：继续提示选择或明确新建，不得随机覆盖。
- 接口失败：保留现有错误提示和不误报保存成功行为。

## 验收标准

- [ ] 相同公司、不同岗位、相同招聘 URL 的录入发送 POST，不覆盖旧岗位。
- [ ] 保存后的公开公司聚合同时包含两个岗位，两个岗位的状态、链接和备注互不覆盖。
- [ ] 相同公司、相同岗位的再次录入仍按既有规则更新目标记录。
- [ ] URL 归一化、登录、普通新建、认证失败和原有插件打包回归通过。
- [ ] 测试 Agent 先提交稳定 `RED_CONFIRMED`；实现 Agent 提交 `READY_FOR_TEST`；测试 Agent 独立提交 `TEST_PASSED`；PM 再验收并设置 `DONE`。

## 风险与测试边界

- 测试必须通过可加载插件、公开弹窗和 HTTP 请求体观察行为，不读取插件生产源码。
- 至少覆盖同链接不同岗位、同岗位链接更新、不同链接不同岗位和现有 URL/hash 回归。
- 后端已经提供同公司 flat POST 追加岗位能力；若公开接口响应未保留两个岗位，应另行记录为后端缺陷，不在本任务扩大范围。

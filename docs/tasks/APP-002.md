# APP-002 创建投递记录 API

- 状态：`DONE`
- 用户价值：登录用户可以新增自己的公司投递记录并立即获得完整记录。
- 范围：`POST /api/v1/applications/`、认证、序列化校验、用户归属绑定。
- 非范围：列表查询、详情、修改、删除、前端表单。
- 依赖：`APP-001`、`AUTH-002`。
- 允许修改范围：测试 Agent：`backend/tests/`、`docs/test-reports/`；实现 Agent：`backend/apps/`、`backend/config/`、迁移和 `docs/implementation-notes/`；项目管理 Agent：仅 `docs/requirements/`、`docs/tasks/`、`docs/acceptance/`。

## 业务规则与公开契约

- `POST /api/v1/applications/` 必须携带 Bearer Access Token，成功返回 `201` 和完整记录。
- 请求接受公司、岗位、状态、投递时间、六个阶段时间、备注；未填时间为 `null`，状态默认 `applied`。
- 后端从 Token 获取 `user`，忽略或拒绝请求体中的 `user` 字段，不能由客户端转移归属。
- `id`、`user`、`current_stage`、`created_at`、`updated_at` 为只读。

## 输入、输出与错误行为

- 未认证：`401`。
- 公司名/岗位名缺失或只含空格、非法状态、非法 ISO 时间：`400 VALIDATION_ERROR`，按字段给 `details`。
- 成功响应包含设计方案规定的完整 snake_case 字段，不返回密码或 Token。

## 验收标准

- [x] 合法请求返回 201，记录归属当前用户且六个阶段可全部为 null。
- [x] 忽略伪造 user 后记录仍属于 Token 用户。
- [x] 所有字段校验、时区时间和默认值行为符合契约。
- [x] 未认证请求不会创建数据。
- [x] 测试先证明创建行为缺失并提交 RED，再由实现和独立复测完成。

## 风险与测试边界

- 不要求创建后自动推进当前阶段；派生规则由模型提供。
- 不在本任务实现搜索、分页或更新。

# WEB-SHARE-001 投递共享页面、浮窗与侧栏

- 状态：PLANNED
- 用户价值：从主侧栏发现用户，申请互看并在同一页面只读浏览对方投递。
- 依赖：SHARE-001 公开 API；WEB-NAV-001/002 与现有登录布局。
- 范围：`/sharing`、共享侧栏入口、默认头像展示、居中/右上浮窗、推荐和 ID 搜索、申请处理与历史、共享用户切换/解除、只读投递分页搜索。
- 非范围：后端、备注共享、通知推送、个人记录编辑流程、部署。
- 角色：根 Agent 项目管理；share_tests 测试；share_implementation 实现。
- 可写范围：测试仅 `frontend/tests/`、`tests/e2e/`、`docs/test-reports/` 与必要测试配置；实现仅 `frontend/src/`、`docs/implementation-notes/`；PM 仅需求、任务、验收目录。

## UI 与 HTTP 公开契约

- 使用 SHARE-001 API，不把用户 ID 放进本人列表请求来伪造跨用户访问。认证延续原守卫与统一 HTTP。
- 侧栏名称“投递共享”，URL `/sharing`；直接打开、刷新和从列表侧栏进入都保留主侧栏，可返回“我的投递进度”/“日历”，桌面收起与窄屏菜单有效。
- 页面标题“投递共享”；显示“我的 ID”与自身头像。未选择用户时主区域内居中较宽浮窗，提供“推荐用户”“换一批”、标签“用户 ID”的数字搜索框与“搜索用户”、发申请按钮，以及“收到的申请”“发出的申请”“已共享用户”。头像/用户名/ID 同时可见。
- 搜索/推荐人员旁“申请互看”；提交时禁止重复发送，成功展示“待对方同意”或同义状态并刷新列表。对传入 pending/connected 关系显示相应状态，不提供重复按钮。无效输入不发请求；404 给出“未找到用户”，网络失败可重试且保留输入。
- 收到 pending 可“同意”/“拒绝”，其他申请仅显示状态；发出的记录区分待处理、已同意、已拒绝、已解除。UI 明示“同意后双方可互相查看，个人备注不共享”。操作失败明确提示；冲突重新读取当前状态。
- 已共享用户名/头像可选择；仅选择 connected 用户才加载共享记录。选择后浮窗在主内容区平滑移动到右上方且宽度变窄，左侧主区域显示选中用户名称/ID及只读记录。保留“返回用户选择”恢复居中宽浮窗和空选择状态。
- 主区域显示公司、岗位、状态、当前阶段、投递链接、投递时间、六阶段时间与时长；有分页（默认20，10/20/50/100）和公司/岗位搜索。不出现编辑、删除或个人备注。加载、空记录、网络重试清晰；快速切换用户/搜索不得用旧响应覆盖当前用户。
- 共享人员可“解除共享”（明确确认），成功刷新名单并在当前被选人解除后清空记录/恢复居中；记录请求返回404提示“共享已失效”并清空此前内容，不能留下旧数据；用户切换时先清理旧记录。
- 窄屏浮窗可调整为紧凑上方布局，记录与导航均可用，不横向溢出；尊重 prefers-reduced-motion。
- 默认头像用8种内置素材/图形对应avatar键，不依赖远端头像服务，保留可读用户名。

## 验收标准

- [ ] 共享入口、直接访问/刷新与页面返回保留侧栏，桌面和移动导航通过。
- [ ] 居中宽浮窗展示推荐、我的ID、搜索及双方申请历史，处理申请有成功/失败状态。
- [ ] 选择已共享用户触发右上移动/缩窄，记录只读且可搜索/分页；返回恢复浮窗。
- [ ] 未授权不能查看、解除/404清除旧记录、快速用户切换无串数据。
- [ ] 有效头像、空/加载/网络失败反馈及移动布局符合要求。
- [ ] SHARE-001/WEB-SHARE-001 整体真实双用户流程与相邻侧栏/日历回归通过，lint/build成功。

## 风险与测试边界

测试仅观察浏览器公开 UI、几何边界与 HTTP mock/真实 API，不读取或枚举 frontend/src/。使用既有 Playwright runner 的公开配置与测试模式，动画结束后比较相对主内容位置及宽度，不断言内部 CSS 类。专项必须覆盖新页面，而非只验证API。如全量出现既有失败须明确归因，不降低断言。测试提交先于实现，各角色单独提交，不推送。

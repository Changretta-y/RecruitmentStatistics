# REL-001 全量质量门禁与发布演练

- 状态：`TEST_FAILED`
- 用户价值：完成系统级交付前检查，确认迁移、质量门禁、健康检查和备份恢复不会阻断发布。
- 范围：完整 CI 顺序、覆盖率门槛、PostgreSQL 迁移演练、备份/恢复演练、发布后健康与核心 API 冒烟。
- 非范围：实际生产发布、购买云资源、长期监控运营和灾备 SLA 承诺。
- 依赖：`E2E-001`、`DOC-001`、`SEC-001`。
- 允许修改范围：测试 Agent：`tests/e2e/`、`backend/tests/`、`frontend/tests/`、`docs/test-reports/`；实现 Agent：CI/运行时配置及各自生产目录、`docs/implementation-notes/`；项目管理 Agent：仅 `docs/requirements/`、`docs/tasks/`、`docs/acceptance/`。

## 业务规则与公开契约

- CI 顺序至少为 Ruff → 后端 pytest/coverage → ESLint/TypeScript → Vitest/coverage → 前端 build → Playwright E2E；任一步失败阻断。
- 后端总体覆盖率不低于 90%，认证/权限/Token 分支 100%；前端总体不低于 80%，Token/刷新/Store 分支 100%，除非项目管理记录有明确豁免。
- 使用临时 PostgreSQL 服务，不以 SQLite 替代；迁移可从空库执行并在升级路径验证。
- 发布演练顺序包含数据库备份、迁移、后端/前端制品、健康检查和核心 API 冒烟；恢复演练必须实际恢复并验证数据。

## 验收标准

- [x] CI 所有质量步骤使用项目锁定的 uv/nvm/npm 环境并在失败时阻断。
- [ ] 全量后端、前端、E2E 和覆盖率报告通过阈值；前端 branches `73.51%` 低于 `80%`，auth store branches `60%`。
- [x] PostgreSQL 空库迁移、升级迁移、备份恢复演练有可追溯输出。
- [x] 发布后 `/api/v1/health/`、认证和投递关键路径冒烟通过。
- [x] 未验证的备份、环境差异或覆盖率豁免被明确记录，不得宣称完成。

## 风险与测试边界

- 本任务是最终系统门禁，不替代各业务任务的 RED 和独立复测。
- 真实生产发布需另行授权；本任务只在隔离环境演练。

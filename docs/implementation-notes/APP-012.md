## 已实现行为

- 新增全局 `Company` 实体：Unicode NFKC + `casefold()` 规范化名称、全局唯一、共享招聘网站、公开创建/搜索/详情/PATCH API。
- 新增 `/api/v1/companies/` 与 `/api/v1/companies/{id}/`，目录只返回公开公司字段；重复创建由 PostgreSQL 唯一约束转为 `409 COMPANY_EXISTS`，包含 `company_id` 和现有公开对象。
- `JobApplication.company` 改为非空保护外键，并以 `(user, company)` 唯一；用户投递、岗位、面试和共享流程仍按当前用户隔离。
- 应用接口支持 `company_id`，同一用户再次提交同公司岗位时追加到既有聚合；旧 `company_name` flat 请求继续兼容并可按一次性规则创建公司，既有全局招聘网站不会被旧 URL 覆盖。
- 新嵌套岗位写入拒绝 `positions[*].application_url`；新岗位不复制招聘网站。旧顶层 `application_url` 作为只读公司级兼容投影，历史非空岗位 URL 仅保留旧响应兼容，不作为新写入来源。
- 保留 APP-011 八值状态、`current_stage`、多岗位共享流程、日历、邮件和 SHARE-001 路径；共享序列化改为使用全局公司的公开名称/招聘网站。
- 前端增加全局公司搜索/选择/创建、409 重名自动选择已有公司、已有公司新增岗位、公司折叠岗位列表、岗位独立编辑入口和共享招聘网站编辑入口；公司招聘网站在公司行只展示一次，岗位表单不再提交招聘网站。

## 数据库迁移

- 文件：`backend/apps/applications/migrations/0006_company_global_directory.py`。
- 迁移顺序：创建 `companies` → 临时可空添加外键 → 跨用户按规范化名称合并并回填 → 删除旧 `(user, normalized company_name)` 约束 → 外键改为非空 `PROTECT` → 添加 `(user, company)` 唯一约束。
- 保留旧 `JobApplication.company_name`、顶层 `application_url` 和岗位 URL 列，供兼容窗口只读投影使用；未静默删除或覆盖历史岗位 URL。
- URL 选择规则固定为旧记录 `created_at`、旧记录 ID、岗位 ID；迁移打印公司数、合并行数、URL 候选数、冲突数和非法候选数。
- 真实 PostgreSQL 存量验证（隔离数据库 `app009_acceptance`）：2 条旧投递、2 个岗位 → 1 个全局公司；`merged_rows=1`、`url_candidates=3`、`url_conflicts=2`、`invalid_url_candidates=0`，2 条投递关系和 2 个岗位全部保留；最早记录规则选出 `https://jobs.second.example`。
- 对非空关系执行逆迁移明确抛出 `IrreversibleError`，提示恢复迁移前备份；未静默降级或丢失新关系。

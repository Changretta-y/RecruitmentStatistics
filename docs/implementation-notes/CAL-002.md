- 状态：`READY_FOR_TEST`
- 修改范围：`backend/apps/calendar_events/`、`backend/config/settings.py`、`backend/config/urls.py`
- 已实现行为：新增需 JWT 认证的 `GET /api/v1/calendar/events/`。接口要求 `start`、`end` 均为严格 `YYYY-MM-DD` 日期，开始日包含、结束日不包含；验证结束日期晚于开始日期且跨度不超过 42 天。缺参、格式错误、无效日期、相等/反向范围和超长范围均返回 `400`、`VALIDATION_ERROR` 与对应参数的 `details`。成功响应包含 `timezone: Asia/Shanghai`、输入日期和完整事件数组。仅查询当前用户的投递；六个阶段按固定代码分别生成事件，保留终态投递中的安排，并按开始时刻、投递 ID、阶段顺序稳定排序。仅返回与北京时间日期窗口相交的事件，午夜结束遵守左闭右开规则，事件原始起止时间不截断；不使用投递列表分页。
- 数据库迁移：无。复用 APP-008 已持久化的六阶段时间及时长。
- 配置变化：将 `calendar_events` 加入 Django 应用配置，并挂载 `/api/v1/calendar/events/` 路由；无运行时依赖变化。
- 已知限制：查询一次加载窗口内的全部匹配投递并返回完整数组，符合 42 天范围和不分页契约；大量安排时响应体会随事件数量增长。候选查询利用阶段最长 1440 分钟的范围进行预筛选，再按各阶段真实时长执行精确交集检查。

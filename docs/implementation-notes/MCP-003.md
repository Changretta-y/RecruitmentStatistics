# MCP-003 实现说明

- 状态：`READY_FOR_TEST`
- 角色：功能实现 Agent
- 范围：持久化 proposal、preview/apply 安全闭环、幂等、冲突检测、审计和 MCP 工具接入。

## 生产改动

- `backend/apps/mcp/models.py`
  - 新增 `ApplicationChangeProposal`：保存语义化操作、目标、规范化变更、原状态指纹、用户/client/resource/scope 绑定、TTL、一次性状态和应用结果。
  - 新增 `ApplicationChangeIdempotency`：以用户、client、操作和 SHA-256 幂等键建立唯一约束，保存请求指纹与原结果。
  - 新增 `ApplicationChangeAudit`：记录 request ID、操作者、client/resource、目标、字段名、脱敏前后摘要、结果和稳定失败码；不保存 token、授权码、密码、SQL 或原始邮件内容。
- `backend/apps/mcp/migrations/0001_initial.py`
  - 为上述三个模型创建表、索引和幂等唯一约束。
- `backend/apps/mcp/tools.py`
  - 新增 `preview_application_change` 和 `apply_application_change` 的输入/输出模型与业务实现。
  - preview 仅读取目标业务数据并持久化短期 proposal，不写投递、岗位或阶段数据。
  - apply 要求严格 JSON 布尔 `confirm=true`，校验用户/client/resource/scope、未过期、未消费和原状态指纹；业务写入、proposal 消费、成功审计和幂等记录在同一事务内完成。
  - 失败、过期、冲突和重放产生审计记录；同一 proposal/幂等键重放原结果，不重复业务写入。
  - 通过 `manage_connection=False` 保证 MCP-002 事务业务函数嵌套在 apply 原子事务时不会提前关闭数据库连接。
- `backend/apps/mcp/server.py`、`backend/apps/mcp/views.py`
  - 工具白名单扩展为五个稳定语义化工具，并为 preview/apply 提供完整嵌套 JSON Schema、structured output 和 `applications:write` per-tool scope。
  - Streamable HTTP 与 Django 兼容入口都拒绝未知顶层字段；不增加 proposal CRUD、审计查询、REST、SQL 或邮件工具。
- `backend/config/settings.py`
  - 新增 `MCP_PROPOSAL_TTL_SECONDS`，默认 600 秒，配置范围 60–900 秒。

# MCP-002 实现说明

- 状态：`READY_FOR_TEST`
- 角色：功能实现 Agent
- 范围：OAuth `applications:write`、MCP 三工具白名单、语义化新增投递、测评/笔试/面试阶段 upsert、当前用户隔离、事务原子性和公开结构化结果。

## 生产改动

- `backend/config/settings.py`
  - OAuth Toolkit scope 增加 `applications:write`，不加入默认 scope。
- `backend/apps/mcp/oauth_views.py`
  - Authorization Server Metadata 和 Protected Resource Metadata 同时声明 `applications:read`、`applications:write`。
  - 授权请求允许申请一个或两个已声明 scope，拒绝未知或重复 scope；不会隐式追加 write scope。
- `backend/apps/mcp/server.py`
  - 版本更新为 MCP-002。
  - tools/list 白名单为 `find_applications`、`create_application`、`upsert_application_stage`。
  - 写工具提供完整输入 schema、写操作说明和结构化输出声明。
  - SDK Streamable HTTP 路由采用 per-tool scope 校验：查询需要 read，写入需要 write；SDK 资源认证、受众校验和 401 仍保留。
- `backend/apps/mcp/views.py`
  - Django 兼容 JSON-RPC 入口按工具返回 HTTP `403 insufficient_scope`。
  - 三个工具均拒绝未知字段，错误结果不暴露 traceback。
- `backend/apps/mcp/tools.py`
  - `create_application`：支持公司名称/公开公司 ID、公司复用、同一用户岗位追加和重复岗位确定性复用；拒绝岗位级 `application_url`、非法状态、无时区投递时间和伪造用户字段。
  - `upsert_application_stage`：支持共享 `assessment`/`written_test`，以及岗位 `interview` 的 first/second/third/hr/other、自定义名称、更新和清空。
  - 所有写操作从已验证 OAuth subject 获取用户，使用事务和当前用户/岗位过滤；调用现有投影函数更新 `current_stage`，不改变保存的 `application_status`。
  - MCP 返回 APP-012 聚合结构、可读 content 和 structuredContent，并过滤空共享阶段和用户内部字段。

## 数据库与配置

- 未新增模型或迁移。
- 使用现有 Company、JobApplication、ApplicationPosition、SharedStage、PositionInterview 和 APP-012 serializer/投影逻辑。
- 运行时依赖和锁文件未变更。

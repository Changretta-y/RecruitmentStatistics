## 已实现行为

- JobApplication 作为公司聚合；ApplicationPosition 保存每条岗位投递的名称、状态、投递时间、链接与备注；PositionInterview 保存稳定 ID 的可重复面试；SharedStage 公司内类型唯一。
- 同一用户的去首尾空白且忽略大小写公司名聚合，重复 POST 追加岗位并返回原公司 ID。数据库约束与用户/公司事务锁避免并发另建公司。
- 嵌套 PATCH 以岗位/面试 ID 更新或无 ID 新增；省略项保留。所有子 ID 严格匹配公司/岗位，跨资源或跨用户返回 404。只读字段、结构、枚举、空名称、日期与时长错误返回 400，嵌套失败原子回滚。
- AI 面、测评、笔试按类型更新；同请求重复类型最终一次生效。时间默认时长 60，修改日期保留时长，清空日期清空时长，时长需 1–1440 的 JSON 整数。nested 明确 null 时长与省略同义；旧 flat 保持 APP-008 校验。
- 子资源提供面试增改删及岗位删除；保留至少一个岗位，公司删除级联删除全部子资源。
- 列表分页单位为公司，岗位名和状态检索返回该公司全部岗位。nested current_stage 按公司共享阶段/全部岗位面试最近日期计算，固定名称映射旧类型，自定义名称直接返回。
- 保留旧 flat 创建/PATCH/返回字段及当前阶段优先级（flow_version=1）。新 nested 流程使用 flow_version=2。旧固定字段为首岗位/固定名称面试与公司共享阶段的兼容投影，既有日历、邮件、共享页面与插件可继续读取。本任务不新增这些渠道对全部岗位自定义面试的展示。

## 数据库迁移

- `0004_applicationposition_positioninterview_sharedstage_and_more` 新建三张子表，先迁移归并，再建立标准化公司唯一约束；保留旧固定字段。
- 每个历史旧记录生成一个岗位，岗位字段、URL、备注、投递时间与状态全部保留。只对有时间的四种旧面试生成记录，并保留时长；未设置时间不生成面试。
- 历史 AI 面与笔试归公司共享阶段；测评默认空。不同非空时间冲突保留最早时间及其对应时长；时间相同以旧 ID 小者稳定选取。
- 迁移标准输出记录 `companies`、`merged_rows`、`shared_time_conflicts`；冲突数量为每家公司/类型不同非空时间数量减 1 的总和。
- 合成历史专项的实际输出：`companies=1 merged_rows=1 shared_time_conflicts=1`，最早 AI 时间及 37 分钟保留，两个岗位链接/备注和面试时长全部通过 API 断言。初始空测试数据库输出三项均 0；这不是生产库冲突审计，部署须捕获实际迁移输出。
- 生产恢复须使用迁移前数据库备份。新模型非空时禁止逆迁移到旧扁平模型，以避免静默丢岗位或重复面试；空数据库允许反迁移供历史基线验证。

# SHARE-001 经同意互相查看投递记录

- 需求来源：2026-09-28 用户新功能请求；用户明确确认申请通过后双方互相可见，并支持解除共享。
- 默认头像：将用户原文“默认头线”理解为默认头像；从内置头像池随机分配、持久化，已有用户也获得头像；不依赖外部图片服务。
- 备注：已询问用户可选偏好，默认个人备注不共享。共享公司、岗位、状态、投递链接、投递时间、六阶段时间和时长、当前阶段、创建及更新时间；不暴露邮箱、密码、Token、备注或其他个人配置。
- 页面：`/sharing`，侧栏入口“投递共享”。通过既有主布局保留侧栏，支持收起/展开及窄屏抽屉，直接打开或刷新也保留。
- 未选用户：主内容区中间较宽浮窗，展示推荐、按数字 ID 搜索、收到和发出的申请、已共享用户及我的 ID。
- 选中已授权用户：浮窗平滑移动到主内容区右上方并变窄；主区域显示该用户只读记录。浮窗可继续搜索、处理申请和切换用户；返回用户选择恢复居中宽浮窗。窄屏布局不得遮住记录和导航，尊重减少动画设置。
- 推荐默认 10 人，后端环境配置 `SHARING_RECOMMENDATION_COUNT`，范围 1～50；随机抽取不重复的其他活跃用户，排除自身、已有待处理申请及已共享用户；不足时返回实际人数。提供“换一批”。
- ID 搜索仅精确查询其他活跃用户的数字 ID；公开信息只有 ID、用户名、头像及与当前用户关系。
- 申请需要对方显式通过，待处理或拒绝不授权。双向待处理不能偷偷自动通过；同一用户对无效、自身、已有待处理或已共享目标申请得到明确错误。
- 双方随时解除共享，服务端下一次请求立即拒绝；原本人 CRUD API 权限隔离保持。解除后可重新申请。
- 范围外：聊天、通知推送、头像上传、替别人编辑或删除记录、自动上线部署。

对应任务：`SHARE-001`（后端与头像）、`WEB-SHARE-001`（页面与导航）。各自必须走角色隔离 TDD。

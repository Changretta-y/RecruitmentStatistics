# APP-009 公司多岗位与投递流程

## 用户需求

一家公司可以有多个投递岗位，每个岗位分别记录投递信息和流程。公司级 AI 面、测评、笔试每种只登记一次；岗位可以有多个面试环节。新增/编辑页面可增加岗位，主页的多岗位公司可展开查看全部岗位和流程。

## 领域与数据规则

- 公司投递是列表分页和详情的聚合单位；同一用户的公司名称去首尾空格并忽略大小写后相同，归为一个公司投递对象。
- 公司下有一个或多个岗位投递。岗位保留自己的岗位名称、状态、投递链接、投递时间、备注。
- 公司级流程类型为 AI 面、测评、笔试；每种在一个公司投递对象下至多一条，有独立可空时间。更新已有类型应覆盖其日期，不能新建重复类型。
- 岗位级面试流程为独立记录，有名称、时间、时长；一个岗位允许多条面试记录，环节名称可以重复。每条记录可独立新增、修改、删除。
- 公司级流程与岗位级面试使用父子归属，任何请求不能读写其他用户/公司的子资源。
- 从旧固定字段迁移：AI 面和笔试字段提升到公司级；测评默认为空；四类旧面试字段转为相应岗位下的面试记录，时长保留。只生成历史中有时间的阶段记录。将同一用户下标准化公司名相同的旧数据聚合并保留全部岗位；同一个公司级类型有多个历史非空时间时保留最早时间并在实现说明报告冲突数。

## 公开 API 契约

继续使用 `/api/v1/applications/`。列表和详情返回公司投递对象；分页总数、搜索/过滤单位为公司对象。

公司对象外形：

```json
{
  "id": 27,
  "company_name": "示例科技",
  "shared_stages": [
    {"type": "ai_interview", "scheduled_at": null, "duration_minutes": null},
    {"type": "assessment", "scheduled_at": null, "duration_minutes": null},
    {"type": "written_test", "scheduled_at": null, "duration_minutes": null}
  ],
  "positions": [
    {
      "id": 52,
      "position_name": "后端开发",
      "application_status": "applied",
      "application_time": null,
      "notes": "",
      "interviews": [
        {"id": 71, "name": "一面", "scheduled_at": null, "duration_minutes": null}
      ]
    }
  ],
  "current_stage": "applied",
  "created_at": "2026-09-29T08:00:00Z",
  "updated_at": "2026-09-29T08:00:00Z"
}
```

- `POST /api/v1/applications/` 接受上述可写字段，`company_name` 非空且 `positions` 至少一项；服务端生成全部 ID/时间戳。
- `PATCH /api/v1/applications/{company_id}/` 局部更新；省略字段不变。岗位集合中已有岗位需含本公司岗位 ID，新增岗位不含 ID；省略岗位不删除既有岗位。显式删除通过岗位子资源 DELETE 完成。已存在的 shared stage type 按类型更新。
- 面试子资源路由固定为 `POST /api/v1/applications/{company_id}/positions/{position_id}/interviews/`、`PATCH /api/v1/applications/{company_id}/positions/{position_id}/interviews/{interview_id}/`、`DELETE /api/v1/applications/{company_id}/positions/{position_id}/interviews/{interview_id}/`。岗位删除使用 `DELETE /api/v1/applications/{company_id}/positions/{position_id}/`。对目标资源不属于该公司或当前用户统一 404。
- 日期接受 ISO 8601 或 null；时长规则沿用 APP-008 的 1–1440 整数和既有空时间联动。公司级阶段名称和值类型由服务端枚举限定为三个类型。
- 创建时用户不能指定公司、岗位、面试 ID、所有者、current_stage 或审计时间戳；PATCH 内已有岗位/面试的 ID 仅用来定位本父资源下的对象，不能修改 ID。引用其他父资源/用户的子 ID 返回 404。
- 保留未认证 401、跨用户或不存在资源 404、输入错误 400 `VALIDATION_ERROR` 和失败原子性。

## 补充边界与兼容契约

- 对已有标准化同名公司的 POST 追加岗位，仍返回 201 和原公司 ID 的完整公司，不新增第二个公司；相同岗位名仍允许多条投递。PATCH 公司名称若与另一公司冲突，返回字段级 400 且不改动任一公司。
- 公司至少保留一个岗位；删除最后岗位返回 400，清空整个公司使用公司 DELETE。
- 同一请求重复提交共享阶段类型按提交顺序更新，最终只保留该类型一条；非法类型返回 400。省略共享类型不清空旧值。
- 嵌套岗位 PATCH 的 interviews 以 ID 更新既有面试、不含 ID 新增、省略项保留；显式移除仍使用子资源 DELETE。
- scheduled_at 新增非空时间而未设时长时默认 60；只改日期保留原时长；清空时间联动清空时长；无时间同时提交非空时长返回字段级 400。
- 岗位 application_url 可写，迁移保留旧链接。旧 flat 创建/PATCH、固定阶段字段与列表展示维持兼容投影，避免既有插件、日历、邮件和共享页面因本次结构变更失效。新编辑界面使用嵌套结构作为持久来源。
- 新嵌套 current_stage 取公司共享流程与岗位面试中日期最近的一项；已知旧环节名返回对应旧类型值，自定义面试返回名称，均无时间返回 applied。保留旧 flat 客户端已有阶段优先级语义。
- 本次不新增日历/邮件对全部岗位自定义面试的展开功能，但必须完成现有接口的兼容回归。
